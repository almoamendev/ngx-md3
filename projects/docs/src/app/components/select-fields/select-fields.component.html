Select fields

Select fields let users choose one or more options from a list. The field shows the current selection and opens a menu with the available options. A searchable field also lets the user type in it to find an option.

  • Every option needs a unique value. supportingText and trailingText are optional, and they are rendered by the menu item inside the options menu.
  • The field reports a single value for single selection, and an array of values for multiple. An empty single selection reports null.
  • The component supports [formControl], formControlName and [(ngModel)] directly on md3-select-field, because the field owns its own input element. The control input does the same job as on the md3-text-field.
  • selected on an option sets the starting selection. A bound form control overrides it: from the first value the control writes, the control is the source of truth.
  • A value that has no matching option yet is kept. It appears as soon as the option list arrives, which is useful when the options are loaded asynchronously.
  • By default the field shows the labels of the selected options, joined with a comma. The text is cut with an ellipsis, so the field shows as many labels as its width allows. Give display-with a function to format the text in another way, for example a count, or a summary in the language of the user. Write the function as an arrow property on your component, so that this stays bound.
  • An empty selection always leaves the field empty, and display-with is not called for it. This keeps the floating label in its place.
  • searchable lets the user type in the field to find an option. While the field has focus it shows the query; when it loses focus it shows the selection again. The options that do not match are hidden from the menu.
  • The search covers the label and the value of an option, and its supportingText and trailingText when they are set. It ignores upper and lower case, spaces and punctuation, so new york, New-York and NEWYORK all find the same option. It does not match across two fields of one option.
  • The query is cleared when the field loses focus, and when the menu closes. A click on an option keeps the focus in the field, so the query stays while the user selects more than one option.
  • The error state comes from the bound control (invalid and touched/dirty), and it is shown on the md3-supporting-text below the field.
  • A leading icon goes in the md3-icon-element="leading" slot. To replace the default arrow, put your own icon in the md3-icon-element="arrow" slot.
