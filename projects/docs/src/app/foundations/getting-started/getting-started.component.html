Getting started

Install the package, wire up one stylesheet, and import the components you need. Every component is standalone, so there is no module to register — the only global step is md3.scss, which carries the design tokens the components read at runtime.

Install

The library declares Angular 22 and @angular/cdk as peer dependencies. The CDK is used for overlays (dialogs, menus, sheets, snackbars) and breakpoint observation, so it must be present in the consuming app.

Add the stylesheet

md3.scss is the single global stylesheet. Without it components render unstyled, because every component's own SCSS resolves its colors, radii, shadows and motion from CSS custom properties that this file defines. Import it once, in your app's global stylesheet, before your own rules.

The path keeps the library's src/ folder because the SCSS ships as a package asset rather than through the package's exports map. If you would rather not repeat it, add the folder to stylePreprocessorOptions.includePaths and import by bare filename — this is what the documentation site itself does.

What the file brings in

Part What it does
Fonts

Google Sans, Roboto and Noto Sans Arabic, plus the Material Icons and Material Symbols families. Loaded from Google Fonts over the network.

Token files

The five files under styles/tokens, covered below.

Base reset

box-sizing: border-box and color: inherit on every element, the default font stack, and language/direction rules that swap the font for Arabic and apply direction from the dir attribute.

Document defaults

html and body sizing, a 16px root font size, and the surface background and on-surface text color that the rest of the library sits on.

Element styles

Styles for the directive-only components that have no stylesheet of their own, such as md3-badge and md3-divider, and the md3-scrollable helper class.

Use a component

Import the directives you need directly into a standalone component's imports array. Nothing is globally registered, so a button pulls in a button and nothing else.

Light and dark schemes

md-scheme.scss defines the light palette on :root, .md-scheme-light and the dark palette on .md-scheme-dark. Light is therefore the default, and switching schemes means toggling a class — usually on <body>.

LayoutService already does this for you. Its darkMode signal writes the md-scheme-dark / md-scheme-light classes onto <body> through an effect, so toggling the theme is a one-line signal update. Note that it defaults to true (dark).

Design tokens

Every visual constant in the library is a CSS custom property, declared in styles/tokens and pulled in by md3.scss. They are plain custom properties on :root, which means they inherit, cascade, and can be overridden at any level — globally, per route, or on a single element — with no rebuild.

File Defines
md-scheme.scss

Color roles

--md-scheme-* — primary, secondary, tertiary and their containers, the fixed variants, error, the surface ramp, on-surface, outline, inverse, scrim and shadow. Declared twice: once for light, once for dark.

md-elevation.scss

Shadows

--md-shadow-0dp, 1dp, 3dp, 6dp, 8dp, 12dp — each a complete three-layer box-shadow built on --md-scheme-shadow.

md-border-radius.scss

Shape

--md-border-radius-none through -xxlarge, plus -rounded for fully rounded shapes. Values are in em, so they scale with the element's font size.

md-motion.scss

Duration and easing

--md-motion- then a set (expressive or standard), a speed (fast, default or slow), a kind (spatial or effects) and finally duration or easing — for example --md-motion-standard-default-effects-easing. Spatial tokens are for movement and size, effects tokens for opacity and color.

md-grid.scss

Layout grid

--md-grid-columns, --md-grid-margin, --md-grid-gutter — redeclared per breakpoint. See grids.

Using tokens in your own styles

Color tokens hold RGB channels (92, 77, 212), not finished colors. That is deliberate: it lets any role be used at partial opacity without a second token for every alpha value. The trade-off is that a color token is never valid on its own — it always has to be wrapped in rgb(). Every other token family holds a complete value and is used directly.

Changing your app's colors

Redeclare the roles you want to change after importing md3.scss. Because your rule uses the same selectors and comes later in source order, it wins without !important and without forking the library's SCSS. You only need to list the roles you are actually changing; anything you leave out keeps its default.

Override both schemes. :root and .md-scheme-dark are independent blocks. When the dark class is on <body>, its declarations sit closer to the components than :root on <html>, so they win by inheritance. Overriding only :root produces an app that is branded in light mode and reverts to the library's default purple in dark mode.

A full Material palette is generated from a source color — the tonal values in md-scheme.scss are annotated with the tone they came from (P-40, N-98 and so on). To rebrand thoroughly rather than tweak a few roles, generate a scheme with the Material Theme Builder and convert its hex output to R, G, B channel triplets.

Scoped overrides

Because tokens are inherited custom properties, the same technique narrows to any subtree. This is the supported way to give one section, dialog or embedded widget its own accent without touching the global scheme.

  • Import md3.scss exactly once. It declares tokens on :root and includes remote font @imports, both of which are wasteful to duplicate.
  • Override tokens rather than component styles. Every component reads its colors, radii, shadows and motion through these properties, so a token change propagates everywhere consistently — including to states and variants you would otherwise have to restyle one at a time.
  • Component-level custom properties (--background-color, --foreground-color, --state-color and similar, set on each component's :host) are a second, narrower layer. Set them on an element to restyle that one instance.
  • The fonts load from Google Fonts at runtime. If your app must work offline or ships with a strict Content-Security-Policy, self-host the families and drop the corresponding @import lines.
