Scaffold

The scaffold is the top-level layout foundation of an app. It arranges a top bar, a bottom bar, a leading rail, a trailing rail, and up to three panes (start, main, end) around the viewport using CSS grid, so every other layout piece — app bars, navigation rails, navigation bars, drawers — has a fixed place to project into.

@if (showTopBar()) {
md3-scaffold-bar="top"
} @if (showLeadingRail()) {
md3-scaffold-rail="leading"
}
@if (showStartPane()) {
md3-scaffold-pane="start"
}
md3-scaffold-pane="main"
@if (showEndPane()) {
md3-scaffold-pane="end"
}
@if (showTrailingRail()) {
md3-scaffold-rail="trailing"
} @if (showBottomBar()) {
md3-scaffold-bar="bottom"
}

API

Name Type Default

md3-scaffold

Root layout container. Takes up the full viewport (100dvh) and has no inputs — every region is provided by projecting content marked with the directives below.

md3-scaffold-bar

Marks projected content as the top or bottom bar (e.g. md3-app-bar, md3-navigation-bar).

input.required<'top' | 'bottom'> required
md3-scaffold-rail

Marks projected content as the leading or trailing rail (e.g. md3-navigation-rail, a drawer).

input.required<'leading' | 'trailing'> required
md3-scaffold-pane

Marks projected content as one of the three content panes, laid out start / main / end. The main pane is where routed content usually lives.

input.required<'main' | 'start' | 'end'> required
  • md3-scaffold is meant to be used once, as the root of your app's layout.
  • Content order inside md3-scaffold does not matter — placement is driven entirely by the region attributes, not document order.
  • Bars and rails are optional: a region with nothing projected into it simply collapses, and the panes grid grows to fill the remaining space.
  • The main pane automatically registers with LayoutService, which exposes its scroll position as the mainScrollTop / mainIsScrolled signals — handy for elevating an app bar once the user scrolls.
  • LayoutService also scrolls the main pane back to the top after every completed Angular Router navigation, since the pane element itself persists across route changes and would otherwise stay scrolled down. This only kicks in when a Router is actually provided in the app.
  • The start and end panes double as portal outlets for SheetsService: side sheets opened with side: 'start' or side: 'end' render into the matching pane when it is present.
